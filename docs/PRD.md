# 사이트 설계도(PRD) — (회사 이름 미정) 화장품 단상자 개발·생산

작성일: 2026-10-17 · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.

## 1. 한 줄 정의
화장품 브랜드의 단상자(제품을 하나씩 담는 종이 상자)를 개발부터 생산까지 맡아 만드는 업체.

## 2. 손님
- 누가: 이미 제품을 판매 중인 화장품 브랜드의 구매·디자인 담당자 (리뉴얼, 거래처 바꾸기, 새 제품 상자 개발)
- 어디서 알고 오나: 네이버·구글 검색, 지인·거래처 소개, 기타 (미정)

## 3. 손님이 궁금한 것 (연락하기 전에)
1. 최소 주문 수량 (몇 개부터 만들어 주는지)
2. 단가·견적 (대략 얼마인지, 견적은 어떻게 받는지)
3. 제작 기간(납기) (주문부터 받기까지 며칠 걸리는지)
4. 샘플·후가공 가능 여부 (샘플을 먼저 받을 수 있는지, 박·형압·코팅이 되는지)
- 기타: (미정)

## 4. 믿게 할 증거 (실제로 있는 것만)
- 제작 사례 사진 (실제로 만든 단상자)
- 공장·설비 사진
- 인증서 (종류 미정 — 실제 보유한 것만 적는다)
- 거래 브랜드 이름·로고 (사이트에 올려도 된다고 허락받은 곳만)
- 기타: (미정)
- 후기: (실제 후기가 생기면 넣는다. 지금은 자리만)

## 5. 누르게 할 버튼 하나
- 버튼 이름: 개발 상담 문의
- 누르면: 문의 폼

## 6. 페이지 구성 (위에서 아래로)
1. 첫 화면 — 한 문장 + [개발 상담 문의] 버튼
2. 제작 사례 — 실제로 만든 단상자 사진
3. 자주 묻는 것 네 가지 — 최소 수량·견적·납기·샘플/후가공 (숫자는 "상담 후 안내")
4. 믿을 수 있는 이유 — 공장·설비 사진, 인증서, 거래 브랜드
5. 후기 자리 (비워 둠)
6. 문의 폼
- 맨 아래: 회사 정보 (이름·위치·연락 방법 — 미정)

## 7. 문의 폼에서 받을 것
- 이름, 연락처
- 출시 희망 시기 (언제까지 상자가 필요한지)
- 개인정보 수집·이용 동의 (필수)

## 8. 정확해야 하는 사실 (사용자가 말한 그대로)
- 단가·견적: 사이트에는 "상담 후 안내"
- 최소 주문 수량: 사이트에는 "상담 후 안내"
- 제작 기간(납기): 사이트에는 "상담 후 안내"
- 회사 이름: (미정)
- 위치: (미정)
- 연락 방법: (미정)

## 9. 이번에 넣지 않을 것
- 결제
- 회원가입·로그인
- 문의 폼에 디자인 파일·도면 올리기
- 새 문의 알림 메일

## 10. 첫 화면 한 문장 후보
1. 화장품 단상자, 개발부터 생산까지 한 곳에서 맡습니다.
2. 브랜드의 첫인상이 되는 단상자, 처음부터 함께 개발합니다.
3. 리뉴얼할 상자도, 새로 만들 상자도 — 개발 상담부터 시작하세요.

## 11. 다음에 할 것
- 회사 이름·위치·연락 방법 채우기 (사이트 만들기 전에 꼭)
- 실제 보유한 인증서 종류, 게재 허락받은 거래 브랜드 목록 정리하기
- 제작 사례·공장 사진 고르기
- 인터뷰에서 '기타'로 고른 손님 경로·궁금한 것·증거 내용 채우기
- 상담부터 납품까지 실제 진행 순서 정리하기
- 문의 폼에 디자인 파일·도면 올리기, 새 문의 알림 메일
- 실제 후기가 생기면 후기 자리 채우기

## 12. 만드는 방법 (클로드가 끝까지 만들 때 기준)
- 분위기: 고급스러운 → (2026-10-17 변경) 사용자가 준 디자인 규칙 "Product-tile whiteout"을 따른다. 연회색(#F5F5F7)·흰색·검정 띠를 모서리 없이 쌓고, 가운데 정렬 제목 + 파란(#0071E3) 둥근 버튼 한 쌍 + 큰 그림 순서로 보여 준다. 원래 사이트(apple.com)의 글·로고·브랜드는 쓰지 않고 스타일만 쓴다. 글꼴은 SF Pro 대신 Pretendard. 실제 사진이 없으므로 첫 화면은 단상자 그림(실제 사례 아님)으로, 사진 자리는 "준비 중"으로 둔다.

## 13. 만드는 순서 (클로드가 처음부터 끝까지 한 번에)
1. 스타일(색·글꼴)을 분위기에 맞게 정하고 첫 화면부터 만든다
2. GitHub 공개 저장소에 올리고 Vercel로 배포해 내 주소를 만든다
3. (문의 저장이 '예'이므로) 문의 폼 → Supabase 저장 → /admin 관리자 페이지까지 만든다
4. 다 만든 뒤 한 번에 보고: 내 사이트 주소 · 관리자 주소 · 확인 방법 · 사용자가 할 일
- 사용자가 직접 할 일(이때만 멈춤): 로그인, 결제, 관리자 비밀번호(ADMIN_PASSWORD) 입력
